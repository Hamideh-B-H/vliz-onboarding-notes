# Vocabularies used in EMO-BON RO-Crates

EMO-BON's semantic uplift (Phase 3) combines several standard vocabularies, each covering a different part of the data. (SOSA itself is covered in more depth in `2.rdf-rdfs-sosa.md` — this file is about how the vocabularies divide responsibility.)

| Vocabulary | Covers | Link |
|---|---|---|
| **Dublin Core / schema.org** | The dataset/crate as a whole: who created it, when, under what license, what it's called | [Dublin Core](https://www.dublincore.org/) · [schema.org](https://schema.org/docs/gs.html) |
| **SOSA** (Sensor, Observation, Sample, and Actuator) | The sampling process itself: what device was used, what procedure, what feature of interest was being sampled | [W3C spec](https://www.w3.org/TR/vocab-ssn/) |
| **Darwin Core** | The biological content that resulted: species found, taxonomy, abundance, collection event details | [dwc.tdwg.org](https://dwc.tdwg.org/) |

**In one sentence:** Dublin Core/schema.org answers "what is this dataset and who made it," SOSA answers "how was the sample taken," and Darwin Core answers "what biology did we find."

## Darwin Core vs Dublin Core

| | Dublin Core | Darwin Core |
|---|---|---|
| Scope | General-purpose — any resource (documents, photos, datasets, websites) | Biodiversity-specific |
| Example terms | `title`, `creator`, `date`, `subject`, `description` | `scientificName`, `decimalLatitude`, `eventDate`, `basisOfRecord`, `habitat` |
| Relationship | The general base | An extension built on top of Dublin Core, adding biology-specific terms |

## How this connects to our own BPNS data (Phase 1 output)

| Your CSV column | Likely vocabulary | Likely predicate |
|---|---|---|
| `collection_date` | Darwin Core | `dwc:eventDate` |
| `scientific_name` | Darwin Core | `dwc:scientificName` |
| `samp_collect_device` | SOSA | `sosa:usedProcedure` |
| `depth` | SOSA | `sosa:hasSimpleResult` (part of the sampling process) |
| Crate-level info (creator, license) | Dublin Core / schema.org | `dc:creator`, `dc:license`, etc. |

This mapping is exactly what Phase 3 (`semantic-uplifting-action`) will actually perform on our Phase 1 output CSVs.
