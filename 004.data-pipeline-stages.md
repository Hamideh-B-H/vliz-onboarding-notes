# Data pipeline stages: raw → filtered → transformed

## How this maps to the 4-phase pipeline we've studied

| Pipeline phase | What we called it | What this note calls it |
|---|---|---|
| Phase 1 | Google Sheets → local CSV (`populate-action`) | **Raw** data |
| Phase 2 | Validate CSVs (`data-quality-control-action`) | **Raw → Filtered** |
| Phase 3 | Uplift to RDF (`semantic-uplifting-action`) | **Filtered → Transformed** |
| Phase 4 | Publish | Transformed data gets published |

The two sections below describe the actual rules likely running inside `data-quality-control-action` (Phase 2) and `semantic-uplifting-action` (Phase 3).

## Raw → Filtered

Transforming raw logsheets into filtered distribution files

### 1. Row Removal (Filtering)
- **Rule:** Drops invalid, failed, or unsequenced samples.
- **Why:** Only successfully processed samples with valid ENA accession numbers (ERSXXXXXX) belong in the public distribution.

### 2. Column Pruning (Cleanup)
- **Rule:** Deletes completely empty measurement columns (e.g., empty chemical parameters like petroleum_hydrocarb, bac_prod).
- **Why:** Reduces file clutter and simplifies down-stream queries.

### 3. Privacy & Administrative Removal
- **Rule:** Removes internal logistics and personal contact details (e.g., store_person, arr_date_hq, ship_date_seq, freezer locations).
- **Why:** Protects internal lab workflows and enforces data privacy compliance while keeping public ORCIDs.

### 4. Formatting & Key Normalization
- **Rule:**
  - Replaces legacy/field IDs (source_mat_id_orig) with clean, standardized primary keys (source_mat_id).
  - Formats all dates into standardized ISO-8601 (YYYY-MM-DD).
- **Why:** Ensures strict relational integrity across observatory, sampling, and measured tables when converting rows into RO-Crate JSON-LD nodes.

## Filtered → Transformed

The transition from Filtered Data to Transformed Data moves the files from clean tabular data into fully semantically mapped metadata.

### 1. Data Restructuring & Reshaping (Long/Tidy Format)
- **Filtered Data:** Uses wide tables where measurements sit in individual horizontal columns (sea_surf_temp, diss_oxygen, nitrate).
- **Transformed Data:** Melts/unpivots wide measurement tables into a vertical long format (variable_name, value, unit, method_uri), creating standardized PropertyValue key-value pairs.

### 2. Semantic Alignment (URI Injection)
- **Filtered Data:** Contains plain text string values for methods and terms (e.g., "CTD", "seawater").
- **Transformed Data:** Maps plain text values to permanent global URIs and ontology terms (e.g., mapping "CTD" to NERC Vocabulary URIs, or "seawater" to ENVO:00002149).

### 3. Direct JSON-LD / RDF Graph Readiness
- **Filtered Data:** Serves as tabular input files stored on disk.
- **Transformed Data:** Mirrors the exact entity node structure required by @graph in ro-crate-metadata.json, assigning explicit @id subjects and @type classes to every row.

### Key Takeaways for Data Engineers

| **Feature** | **Filtered Data** | **Transformed Data** |
|---|---|---|
| **Primary Goal** | Cleaning, column pruning, and row validation | Semantic mapping and FAIR ontology encoding |
| **Structure** | Tabular (Wide format CSVs) | Key-value / Linked Data pairs (Long format) |
| **Identifiers** | Local IDs (EMOBON_BPNS_Wa_1) | Globally resolved URIs / Schema IRIs |
| **Downstream Target** | Quality Control validation steps | Final ro-crate-metadata.json and all-triples.ttl |
