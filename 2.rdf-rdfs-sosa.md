# RDF, RDFS, and SOSA

## Core idea: everything is a triple

Every RDF statement has three parts:

SUBJECT → PREDICATE → OBJECT


Example: "This water sample has collection date 2021-07-01"

<.../EMOBON_BPNS_Wa_1> dwc:eventDate "2021-07-01"


- **Subjects and predicates** must be unique web URIs (URLs) — this is what makes them globally unambiguous. A domain you control (e.g. `data.emobon.embrc.eu`) guarantees uniqueness without needing a central authority.
- **Literals** (raw values like `"7.19"` or `"Dissolved Oxygen"`) are just strings in quotes — no URI, a dead end in the graph.
- **Objects can be either**: a literal, or another URI pointing to a different subject (which can have its own triples). This is what makes RDF a *graph*, not a flat list — you can "walk" from one entity to another by following links.

## Turtle (`.ttl`) syntax

Human-readable shorthand for writing RDF. Uses `@prefix` declarations at the top so full URIs don't need to be repeated.

## RDFS (RDF Schema) — the rulebook

RDFS defines the rules/hierarchy that organize raw triples into a structured model:

| RDFS term | Meaning | Code/DB analogy |
|---|---|---|
| `rdfs:Class` | Defines a category/template for entities | SQL table / OOP blueprint |
| `rdfs:subClassOf` | Child/parent class hierarchy | `class Child(Parent):` |
| `rdfs:domain` | Restricts which Class can be the **subject** for a property | Foreign key constraint |
| `rdfs:range` | Restricts what type/Class can be the **object** for a property | Column data type constraint |
| `rdfs:label` | Short human-readable name | Column header / alias |
| `rdfs:comment` | Detailed human-readable documentation | Tooltip / docs |

## SOSA (Sensor, Observation, Sample, and Actuator)

The official W3C/OGC international standard ontology for structuring scientific observations, sensors, and physical samples.

Namespace: `@prefix sosa: <http://www.w3.org/ns/sosa/> .`

Key concepts:
- **`sosa:Observation`** — the measurement event itself (e.g. taking a measurement at a specific time/station)
- **`sosa:observedProperty`** — links the observation to the specific quality/parameter measured (e.g. dissolved oxygen, temperature)
- **`sosa:hasResult`** — connects the observation to its outcome (numerical value + unit)
- **`sosa:Sample`** — the physical oceanographic sample (water or sediment) collected

## Annotated example (from EMO-BON data)

```turtle
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
@prefix sosa: <http://www.w3.org/ns/sosa/> .
@prefix qudt: <http://qudt.org/schema/qudt/> .
@prefix xsd: <http://www.w3.org/2001/XMLSchema#> .

# 1. RDFS SCHEMA DEFINITION
sosa:Observation a rdfs:Class ;
    rdfs:label "Marine Observation" ;
    rdfs:comment "An act of carrying out a procedure to estimate or calculate a value of a property." .

sosa:observedProperty a rdf:Property ;
    rdfs:domain sosa:Observation ;
    rdfs:range sosa:ObservableProperty .

# 2. INSTANCE DATA (from EMOBON marine observation)
<.../EMOBON_BPNS_So_11#diss_oxygen> a sosa:Observation ;
    sosa:observedProperty <.../dissolved_oxygen> ;
    sosa:hasResult [
        qudt:numericValue "7.19"^^xsd:decimal ;
        qudt:unit <.../KGUM>
    ] .

<.../dissolved_oxygen> a sosa:ObservableProperty ;
    rdfs:label "Dissolved Oxygen" .
```

## One-line summary

"RDF is the underlying graph model used to connect data using triples. Turtle (.ttl) is the clean, human-readable file language used to write that RDF data."
